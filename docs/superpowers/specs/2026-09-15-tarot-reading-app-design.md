# 小艾塔罗 设计文档

日期：2026-09-15

## 用途

小艾在微信上给别人做塔罗测算。她用实体韦特牌抽三张牌，在这个 app 里录入客人问题和牌面，由 Claude 生成解读草稿，她修改后导出长图或微信文字发给客人。每次测算按时间存档。手机和电脑都用，数据同步。

使用者只有小艾一人。客人不接触 app，只收到导出的长图或文字。

## 范围

做：三张牌阵；韦特 78 张；复制提示词到 Claude、再把解读粘回来；长图和微信文字两种导出；白天/夜间两套主题；按时间存档与搜索；手机电脑同步；断网可用。

不做（本期）：app 内直接调用 Claude API（结构上预留，见「以后升级」）；电子抽牌；拍照识牌；其他牌阵；客人档案；多用户。

## 页面与流程

共三个页面。

登录页：邮箱加密码登录，沿用「河」和「小熊红黑榜」所在的同一个 Supabase 项目（qsqcmsznxhuwjrjnihob）和同一个账号。不用邮件登录链接，因为从主屏幕打开的网页应用点链接会跳到 Safari，登录状态进不了 app；也不用邮箱验证码，因为那需要改项目的邮件模板，会影响另外两个 app。

记录列表页：按创建时间倒序。每条显示日期、客人称呼、问题前若干字、三张牌缩略图；解读为空的标「未完成」。顶部搜索框按称呼或问题关键词过滤。右下角新建按钮。

测算页：新建和打开旧记录共用。一整页向下滚动，不做分步向导，内容边填边自动保存。从上到下四段：

问题段。客人称呼、问题原文、牌阵位置。位置预设三组：过去/现在/未来，现状/阻碍/建议，你/对方/关系走向；另可选自定义，手填三个位置名。

牌面段。三个牌位并排。点牌位弹出选牌面板，按大阿卡纳、权杖、圣杯、宝剑、星币分组，顶部可输入搜索（如「塔」「宝剑三」）。选中后显示牌面图，下方正位/逆位切换，逆位时图片旋转 180 度。

解读段。「复制提示词」按钮，问题、三个位置、三张牌未填全时不可点。下方大文本框粘贴解读，可直接修改。

导出段。「生成长图」弹出预览，带白天/夜间开关，默认跟随当前界面主题；手机上长按保存或调起系统分享，电脑上下载。「复制微信文字」把文字版放进剪贴板。

## 提示词

由 app 根据当前记录拼装，模板放在单独一个文件（`src/prompt/template.ts`），口吻调整只改这个文件。

内容依次为：

角色：使用韦特体系的专业塔罗师，为付费客人做三张牌解读。

材料：客人称呼、问题原文、三个位置名、每张牌的中文名与正逆位。

写作要求：每张牌先讲该牌在该位置上的含义，再落到客人的具体问题；讲清三张牌之间的关联与走向；整体解读给出明确判断，不模棱两可；建议具体到可执行的行动；口吻专业克制，不渲染恐惧，不写鸡汤；全文 600 到 900 字。问题涉及健康、怀孕、法律纠纷时，只谈心态与方向，不给医疗或法律结论，也不在正文中写免责声明。

输出格式：严格使用以下五个标题，标题独占一行，不加其他标题或 Markdown：

```
【第一张｜{位置1}｜{牌名}·{正位/逆位}】
【第二张｜{位置2}｜{牌名}·{正位/逆位}】
【第三张｜{位置3}｜{牌名}·{正位/逆位}】
【整体解读】
【建议】
```

## 解读拆分

粘回来的文本按以 `【` 开头、`】` 结尾的独占行拆分。识别出「第一张/第二张/第三张/整体解读/建议」五段时，按段排版。标题里的牌名与记录不一致时以记录为准，不报错。任何一段缺失或完全没有标题时，退回为整段文本排版。拆分失败永远不阻止导出。

## 导出

长图：固定宽 1080 像素，按选定主题渲染后转为 PNG。结构从上到下：页眉（TAROT READING 小字、问题、称呼·日期·三个位置名）、三张牌并排（牌面图加位置名和牌名正逆位）、三张牌各自的解读段、整体解读、建议、底部署名「小艾」。拆分失败时牌面以下为一整段解读。字体嵌入 Noto Serif SC 网络字体，保证各设备导出一致。

两套主题共用同一排版，只换配色（依据头脑风暴中确认的样式小样）：

白天「米白纸页」：米白底 #f4efe6，正文深墨 #2b2620，标题暗金棕 #6d5530，分隔细金线 #b89a5e，牌面白边细框。

夜间「深夜烫金」：深蓝底 #141a2b，正文米色 #d6d1c4，标题与点缀金色 #c9a95c，分隔线 #2e3650，牌面金色细框。

微信文字：首行复述问题，随后三张牌各一段（「第一张 · 位置 · 牌名 正位」起头），再是整体解读、建议，段间用一行「——」分隔，末尾署名「小艾」。不含方括号标题。

## 主题

app 界面跟随系统深浅色自动切换白天/夜间主题。导出长图的主题开关独立，默认同当前界面，选择记入该条记录。

## 数据与同步

前端：Vite + React + TypeScript，做成可添加到主屏幕的网页应用（PWA），部署 GitHub Pages。

后端：Supabase（与「河」「小熊红黑榜」共用项目），邮箱密码登录。一张表 `readings`：

```
id uuid 主键
user_id uuid，默认 auth.uid()
created_at timestamptz
updated_at timestamptz
client_name text
question text
spread_preset text   -- past_present_future / situation_obstacle_advice / you_them_outcome / custom
positions text[3]
cards jsonb          -- [{ "id": "swords-03", "reversed": true }, ...]，未选为 null
interpretation text
export_theme text    -- day / night
```

开启行级权限，仅 `user_id = auth.uid()` 可读写。「未完成」由 `interpretation` 为空推导，不单独存。

保存：编辑停顿 1 秒后保存，同时写入本地 IndexedDB。离线时只写本地并标记待同步，恢复网络后按 `updated_at` 推送；同一条两端都改过，以最后修改为准。启动时从 Supabase 拉取并与本地合并（同样按 `updated_at`）。

牌面图：78 张韦特 1909 年原版（公共领域，取自 Wikimedia Commons），压缩为 WebP 打包进 app，总量约 2 到 3 MB，并由 Service Worker 缓存。本地打包保证离线可用，也避免导出时跨域图片导致画布失败。牌的中英文名与图片文件对应表放在 `src/cards/deck.ts`。

## 出错处理

复制提示词失败：弹出提示词全文，供手动全选复制。
解读拆分失败：整段排版，照常导出。
保存失败或离线：页面角落显示「未同步」，同步成功后消失。
长图生成失败：提示重试，并保留「复制微信文字」可用。
登录失效：跳登录页，本地未同步数据保留，登录后继续推送。

## 测试

自动测试（Vitest）：提示词拼装（各预设与自定义位置、正逆位文字）；解读拆分（标准格式、标题缺失、多余空行、全角半角混用、完全无标题、标题牌名与记录不符）；微信文字生成；本地与远端记录合并规则。

手动验证：在手机尺寸和电脑尺寸各走一遍新建、选牌、复制提示词、粘贴解读、两种主题导出长图、复制文字、断网录入再联网同步的完整流程。

## 以后升级：app 内生成

新增一个 Supabase Edge Function，接收记录 id，服务端拼提示词并调用 Claude API，返回解读写入 `interpretation`。API key 只存在 Supabase 密钥中。前端把「复制提示词」旁边加一个「生成」按钮，其余流程不变。提示词模板届时移到可被函数和前端共用的位置。

## 2026-10-31 追加：八字背景

测算页「问题」下方新增可选的「八字」段：公历或农历（含闰月）出生日期、出生时间（不详可留空）、性别。由 `lunar-javascript` 在本地排出四柱、十神、日主、五行计数、大运与流年，并在页面上预览供核对。

填了出生信息时，提示词附上排好的命盘（要求 Claude 直接使用、不自行排盘），输出多一个【命盘参考】标题，位于三张牌之后、整体解读之前；全文放宽到 800 到 1100 字。八字只作背景，判断仍以三张牌为主。拆分时【命盘参考】可有可无，长图在该段顶部画出四柱，微信文字多一段「命盘参考」。

数据库 `readings` 表新增 `birth jsonb` 列（见 `supabase/readings.sql`）。时辰不详时只排三柱；排盘按出生地钟表时间，不做真太阳时校正。
